# Инструменты проекта простым языком

Это отдельная памятка по инструментам из схемы локального варианта MVP.

Важно: 1С работает не с файлами из локальной папки, а с данными пакетов из `PostgreSQL`. Локальная папка нужна как архив фотографий и файлов результата.

| Инструмент | Что делает | Объяснение простыми словами |
|---|---|---|
| MAX-бот | Принимает сообщения и фотографии от сотрудника. | Это точка входа для пользователя. Через бота человек отправляет документы, выбирает организацию и склад, а потом завершает пакет. |
| MAX API | Передаёт сообщения, фотографии и ответы между ботом и сервисом. | Это технический канал связи с MAX. Благодаря ему сервис получает фото и может отправить человеку ответ. |
| FastAPI | Управляет логикой сервиса и связывает между собой бот, базу и распознавание. | Это главный "мозг" проекта. Он принимает команды, создаёт пакеты документов, меняет статусы и отдаёт данные для 1С. |
| Bot handlers | Обрабатывают действия пользователя по шагам. | Они решают, что делать после каждого сообщения: сохранить фото, предложить выбрать склад, отправить пакет на распознавание. |
| PostgreSQL | Хранит карточки пакетов, их статусы и результат распознавания. | Это основное деловое хранилище проекта. Именно отсюда 1С получает готовые пакеты со статусом `Ready` и сюда же возвращает `Imported` или `Error`. |
| Локальная папка на ПК | Сохраняет исходные фотографии и служебные файлы пакета. | Это файловый архив проекта. Фото лежат локально на компьютере, но 1С не использует эту папку для создания документов напрямую. |
| OCR worker | Берёт пакет в работу и запускает распознавание. | Это фоновый обработчик, который не мешает работе бота. Он проверяет очередь, забирает новые пакеты и доводит их до результата. |
| `worker_jobs` | Очередь задач на обработку. | Это список того, что нужно распознать. Когда пользователь завершает пакет, именно сюда попадает задача для фонового worker. |
| Yandex Vision OCR | Считывает текст и таблицы с фотографий документа. | Этот инструмент превращает изображение в текстовые данные. Он помогает "увидеть", что написано в накладной. |
| YandexGPT | Приводит распознанный текст к понятной структуре данных. | Он раскладывает сырой текст по полям: номер документа, дата, поставщик, строки товаров и суммы. Благодаря этому результат можно использовать дальше в 1С. |
| 1С:ERP | Показывает готовые пакеты оператору и помогает загрузить их в учётную систему. | Оператор обновляет список, выбирает пакет со статусом `Ready` и создаёт документ. После этого 1С возвращает в базу итоговый статус `Imported`, а если что-то пошло не так — `Error`. |

Источник: `docs/mvp-process-local.drawio`  
Вариант: MAX + локальное хранилище + PostgreSQL + 1С.
