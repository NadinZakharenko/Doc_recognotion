# MVP backlog: MAX → OCR → 1С (ТОРГ-12 / УПД)

Документы: только ТОРГ-12 и УПД.  
Выход: `result.json` (`specs/result.schema.json`).  
API для 1С: `specs/openapi.yaml`.  
Пакет: несколько фото + кнопка **«Завершить пакет»**.

---

## Итерация 1 — каркас (бот + БД + хранилище)

Цель: принять фото в MAX, собрать пакет, сохранить файлы и метаданные, отдать статусы пользователю. OCR и 1С — заглушки.

### Бот MAX
- [ ] Создать бота RWB, webhook + проверка `X-Max-Bot-Api-Secret`
- [ ] Команды/кнопки: выбрать организацию, выбрать склад, «Завершить пакет», «Мой контекст», «Сменить склад»
- [ ] Приём одного/нескольких фото → добавить в текущий `draft`-пакет пользователя
- [ ] Ответы: «фото N добавлено», «пакет завершён, в очереди», ошибки ввода
- [ ] Идемпотентность webhook (повторная доставка MAX)

### СУБД / хранилище
- [ ] PostgreSQL: `users`, `orgs`, `warehouses`, `user_bindings` (`max_user_id → org_id, warehouse_id`), `packets`, `packet_files`, статусы
- [ ] Файловое хранилище: локальный диск или SMB (адаптер под замену на MinIO)
- [ ] Структура путей: `{org_id}/{warehouse_id}/{packet_id}/images/...`
- [ ] Миграции схемы БД

### Интеграционный сервис
- [ ] HTTP-сервис: webhook MAX, внутренние health-check
- [ ] Жизненный цикл пакета: `draft → queued` по кнопке «Завершить пакет»
- [ ] Заглушка worker: `queued → ready` с пустым/фикстурным `result.json`
- [ ] Конфиг: токены, пути, список org/warehouse (seed)

### 1С
- [ ] Не трогаем (или только ознакомление с OpenAPI)

**DoD итерации 1:** товаровед выбирает склад, шлёт 2–3 фото разными сообщениями, жмёт «Завершить пакет», пакет в БД со статусом `ready` и файлами на диске.

---

## Итерация 2 — OCR + API для 1С

Цель: реальное распознавание во внешний LLM/Vision и контракт, по которому 1С может забирать пакеты.

### OCR worker
- [ ] Очередь на PostgreSQL (`SKIP LOCKED`) или простой poller
- [ ] Статусы: `queued → processing → ready | error`
- [ ] Вызов внешнего Vision/LLM API по схеме `result.schema.json`
- [ ] Валидация JSON Schema на выходе; при провале — `error` + сообщение в MAX
- [ ] Расчёт `overall_confidence`, заполнение `warnings` (totals mismatch, пустые поля)
- [ ] Сохранение `result.json` рядом с images
- [ ] Ретраи внешнего API (timeout, 429, 5xx) с лимитом

### API для 1С (`openapi.yaml`)
- [ ] `GET /packets?status=ready&org_id&warehouse_id`
- [ ] `GET /packets/{id}`
- [ ] `GET /packets/{id}/result`
- [ ] `POST /packets/{id}/imported` (идемпотентно)
- [ ] Bearer-токен для 1С
- [ ] Пример ответа / Postman-коллекция (опционально)

### Бот MAX
- [ ] Уведомления: обработка → готово / ошибка распознавания
- [ ] Уведомление после `imported`

### СУБД
- [ ] Поля `recognized_at`, `imported_at`, `imported_by`, `ptu_ref`, `error_message`, `document_type`, кэш шапки для списка

### 1С
- [ ] Ещё без UI: можно проверить API через консоль/Postman

**DoD итерации 2:** по тестовым фото (когда появятся) получается валидный `result.json`; `list/result/imported` работают; бот шлёт статусы.

## Итерация 3 — доработка 1С:ERP

Цель: оператор из 1С видит готовые пакеты и вручную создаёт черновик ПТиУ.

### 1С:ERP
- [ ] HTTP-клиент к Integration API (токен, SSL/on-prem endpoint)
- [ ] Команда/форма «Загрузить приходную из бота»
- [ ] Список пакетов `ready` с фильтром org/warehouse (как в 1С у пользователя)
- [ ] Просмотр полей result (шапка + таблица) в форме 1С
- [ ] Создание **непроведённого** ПТиУ из result (номенклатура — ручной подбор / простой поиск по наименованию)
- [ ] Вызов `POST .../imported` с `ptu_ref` и `imported_by`
- [ ] Обработка `error` / повторный запрос списка по кнопке или регламенту

### Интеграционный сервис
- [ ] Логи аудита вызовов 1С
- [ ] Защита: пакет `imported` не отдаётся в основном списке `ready`

### Бот
- [ ] Текст уведомления: «Пакет {номер/дата} загружен в 1С»

**DoD итерации 3:** полный путь фото → ready → черновик ПТиУ → imported → уведомление в MAX.

## Вне скоупа MVP (бэклог позже)

- Автозакрытие пакета по таймауту
- Превью таблицы в MAX / правка в чате
- Маппинг MAX-пользователь ↔ пользователь 1С
- Автосопоставление НСИ / автопроведение
- Nextcloud, Excel, роли, ПДн-контур, retention-политики
- Дедупликация документов, детект «два документа в одном фото»
- Локальный OCR вместо внешнего API
- MinIO/S3 как замена диска

---

## Зависимости и риски

| Риск | Митигация |
|------|-----------|
| Нет образцов ТОРГ-12/УПД | Параллельно собрать 20–50 фото до/во время итерации 2 |
| Качество внешнего LLM | Жёсткая JSON Schema + `warnings`; правки только в 1С |
| Нестабильность внешнего API | Ретраи, статус `error`, ручной перезапуск пакета (пост-MVP кнопка) |
| Доработка 1С дольше бота | Итерации 1–2 не блокируются: контракт OpenAPI уже зафиксирован |

---

## Порядок работ (рекомендуемый)

```text
Итерация 1: Bot + DB + Storage + stub ready
        ↓
Итерация 2: OCR worker + OpenAPI (можно начать API сразу после модели данных)
        ↓
Итерация 3: 1С HTTP + форма ПТиУ
```

Параллельно с итерацией 1: сбор образцов документов и seed справочников org/warehouse.
